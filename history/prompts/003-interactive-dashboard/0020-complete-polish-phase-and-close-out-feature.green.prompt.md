**T108** (accessibility pass) found no icon-only buttons needing ARIA labels in any of the 5 new pages (all actions are text-labeled), and confirmed every form input has a proper `<label htmlFor>` pairing. Live-tested `Drawer`'s focus trap and hit a genuine methodology snag: the first attempt used CDP's `Input.dispatchKeyEvent` for Tab, which produced results that looked like a real focus-trap-escape bug (focus appearing to leave the drawer for the page's sidebar nav after a few Tab presses). Rather than filing that as a bug immediately, isolated the question by dispatching an untrusted native `document.dispatchEvent(new KeyboardEvent(...))` instead — which only the app's own JS listener can respond to, with no ambiguity about whether synthetic CDP input drives real browser focus-traversal — and got a clean, correct result: Tab from the last focusable element wraps to the first. Confirmed the same for Escape (closes + restores focus to the exact triggering element), once a timing bug in my own test (checking DOM state synchronously before React's re-render had flushed) was caught and fixed. Documented the CDP-Tab-unreliability finding plainly so a future verification pass doesn't waste time rediscovering the same false alarm.

**T110** (quickstart.md smoke test) skipped re-verifying scenarios already covered live during their own story's implementation (order status visibility, analytics ranges, inventory filtering, product-to-shop visibility, promotion-to-cart) and focused on what hadn't been explicitly exercised: the FR-035 non-admin rejection (confirmed at both the API layer — 403 — and the route layer — redirect to `/admin/login`), and the notification mark-read flow (confirmed against 6 real unread notifications generated by this session's own test data; "Mark all read" correctly fired all 6 API calls, verified via a direct re-check that unread count dropped to 0, with a fresh page load confirming the badge correctly disappeared).
